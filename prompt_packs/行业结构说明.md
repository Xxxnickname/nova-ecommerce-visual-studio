# 行业标准套图结构说明（V3.1）

## 结构依据

不再使用自拟的 12 个“详情页模块”。

采用 Skill 中明确的行业结构：

1. `ecom-details-image`：电商整图默认 **5 张主图 + 7–9 张详情页**；多角度至少 4 种，至少 2 张特写/微距；背景在 2–3 种同体系底色间交替。
2. `ecommerce-detail-page-generator-zh`：详情页按买家决策路径组织，每页只回答一个主要问题。
3. `ecom-image2`：多图必须使用 Campaign Style Lock；单页只能改变画面目的、主体动作、局部构图、短文案。

本项目采用 **5 张主图 + 7 张详情页 = 12 张**。

## 主图结构（1:1 / 2K）

| 编号 | 行业职责 | 页面作用 |
|---|---|---|
| M01 | 白底首图 | 商品识别、平台合规、无广告字 |
| M02 | 核心卖点 | 第一购买理由，短标题 |
| M03 | 质地细节 | 微距证明质地和材质 |
| M04 | 场景使用 | 通勤/梳妆场景代入 |
| M05 | 规格与包装 | 容量、防晒、包装内容，完成购买信息确认 |

## 详情页结构（4:5 / 2K）

| 编号 | 行业职责 | 页面作用 |
|---|---|---|
| D01 | 首屏承接 | 延续主图，建立品牌与产品定位 |
| D02 | 痛点放大 | 提出厚重、假面、不贴肤等需求 |
| D03 | 质地机制 | 用膏体与表面光泽解释轻盈、柔焦 |
| D04 | 核心利益 | 3 个主要利益，竖屏信息带 |
| D05 | 使用方法 | 三步上妆，降低理解成本 |
| D06 | 场景覆盖 | 通勤、约会、旅行三种使用情境 |
| D07 | 规格收束 | 规格、包装内容、品牌收束，不虚构优惠 |

## 统一与变化

**统一**：商品身份、色板、5000K 色温、字体气质、材质语言、光线质量、信息网格。

**变化**：页面职责、镜头、景别、背景材质、产品占比、文案位置、短文案。

**禁止**：12 张中出现连续 3 张同一背景；连续 3 张同一角度；每张都是左文右图；用同一块石材台复制全套。

## 提示词方式

每条 Prompt 由 6 段组成：

1. `REFERENCE ROLE`：真实商品参考与不可变项。
2. `CAMPAIGN LOCK`：整套视觉合同。
3. `PAGE CONTRACT`：页码、行业职责、买家问题。
4. `VISUAL`：画幅、产品占比、场景、构图、镜头、光影、材质。
5. `COPY`：短标题、短标签、文字安全区、后期正文位置。
6. `CONSTRAINTS`：具体负面清单与质检门。

## 模型与参数

- 模型：`doubao-seedream-5-0-flash-260915`。
- 主图：1:1，2K。
- 详情页：4:5，2K。
- 商品参考：真实实拍图，不使用 AI 重绘图作为参考。
- 长文案不在生图阶段直接渲染，统一后期排版。
- 不在 Prompt 中写 `--ar`、`--v` 等 Midjourney 参数。

## 第一性原则

`商品事实 → 买家问题 → 行业页面职责 → 可见证据 → 镜头与材质 → 文案层级 → 生成参数 → 质检`

只要某一项不能落到这条链路里，就不放进最终 Prompt。提示词详细的目的不是堆词，而是让模型没有空间乱猜。
